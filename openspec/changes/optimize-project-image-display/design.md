## Context

**当前状态：**
项目详情页（`ProjectDetailPage.vue`）的图片画廊使用固定布局：
- CSS 类 `.gallery-item` 设置了固定的 `aspect-ratio: 16/10`（横屏比例）
- 图片使用 `object-fit: cover` 填充容器，导致竖屏照片被裁剪顶部和底部
- 网格布局使用 `grid-template-columns: repeat(auto-fill, minmax(260px, 1fr))`

**问题影响：**
- 移动应用类项目（如"美荟商城 - Flutter 电商平台"）的截图多为竖屏（9:16 或类似比例）
- 当前实现导致这些截图只能显示中间部分，丢失大量信息
- 用户无法看到完整的界面截图，严重影响项目展示效果

**约束条件：**
- 必须保持响应式设计，适配不同屏幕尺寸
- 需保留现有的 lightbox 点击放大功能
- 不能破坏现有项目的数据结构（`projects.ts` 中的 gallery 数组）
- 应保持视觉美观性和一致性

## Goals / Non-Goals

**Goals:**
- 实现自适应图片展示，支持竖屏、横屏、方形等多种比例
- 确保所有图片完整显示，无裁剪
- 保持网格布局的美观性和对齐
- 支持响应式设计，在移动端和桌面端都有良好体验
- 保留 hover 效果和 lightbox 功能

**Non-Goals:**
- 不修改数据结构或后端接口
- 不添加图片懒加载之外的新的性能优化
- 不改变 lightbox 组件的行为
- 不支持图片上传或编辑功能

## Decisions

### 决策1：采用 object-fit: contain 替代 cover

**选择：** 使用 `object-fit: contain` 确保图片完整显示

**理由：**
- `contain` 会保持图片比例并完整显示在容器内
- 配合背景色填充空白区域，视觉效果整洁
- 实现简单，兼容性好

**替代方案考虑：**
- ❌ 动态 aspect-ratio：需要 JavaScript 计算图片实际比例，增加复杂度
- ❌ 移除固定高度：会导致网格行高不一致，视觉混乱
- ✅ **选用方案**：保持固定容器大小，用 contain 显示完整图片

### 决策2：使用统一的正方形或接近正方形容器

**选择：** 将 `aspect-ratio` 从 `16/10` 改为 `1/1`（正方形）或 `4/3`

**理由：**
- 正方形容器对竖屏和横屏图片都较为友好
- 竖屏图片在正方形容器中显示面积较大（相比 16:10）
- 网格布局更整齐统一
- 4:3 也是不错的选择，稍微偏向横屏但也能容纳竖屏

**替代方案考虑：**
- ❌ 保持 16:10：仍然会过度裁剪竖屏图片
- ❌ 使用 masonry 布局（瀑布流）：实现复杂，且可能导致对齐问题
- ✅ **选用方案**：使用 `aspect-ratio: 1/1` 或 `4/3`

### 决策3：添加背景色填充空白区域

**选择：** 为 `.gallery-item` 添加浅色背景

**理由：**
- 当使用 `object-fit: contain` 时，图片可能无法填满容器
- 背景色可以避免空白区域显得突兀
- 与整体设计风格保持一致（使用 `var(--bg)` 或浅灰色）

### 决策4：可选优化 - 添加图片加载状态

**选择：** 可选地添加 loading 占位符

**理由：**
- 提升用户体验，避免布局抖动
- 可以使用 CSS 的 `background-color` 作为简单占位
- 不强制要求，可作为增强功能

## Risks / Trade-offs

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 正方形容器空间利用率降低 | 横屏图片在正方形容器中显示较小 | 使用 `aspect-ratio: 4/3` 平衡；或考虑动态计算 |
| contain 模式下图片周围有空白 | 视觉上可能有留白 | 添加匹配主题的背景色 |
| 不同比例图片混排时高度一致但宽度已固定 | 可能看起来不够"整齐" | 这是预期行为，保证完整性优先 |
| 大图在小容器中细节不清 | 用户可能看不清细节 | 已有 lightbox 功能可点击查看大图 |

**权衡取舍：**
- **完整性 vs. 填充率**：选择完整性，牺牲一些空间利用率
- **简洁性 vs. 灵活性**：选择 CSS-only 方案，避免 JS 复杂度
- **一致性 vs. 自适应性**：选择适度的自适应性，保持基本一致的外观

## Migration Plan

**部署步骤：**
1. 修改 `src/style.css` 中的 `.gallery-item` 样式
2. 测试不同比例的图片展示效果
3. 验证响应式布局在不同屏幕尺寸下的表现
4. 确认 lightbox 功能正常工作

**回滚策略：**
- 样式修改可通过版本控制快速回滚
- 无数据库迁移或 API 变更，风险极低
